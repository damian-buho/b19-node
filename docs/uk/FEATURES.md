# Можливості

## Можливості проєкту

### Автоматична встановлення npm та збірка

- Залежності встановлюються автоматично, якщо при збиранні є `package.json` — без додаткових налаштувань у Dockerfile.
- Аутентифікація приватних реєстрів здійснюється через секрети BuildKit, ніколи не вбудовуючись в образ.
- Якщо існує скрипт `build`, він виконується автоматично після встановлення — образи виробництва виходять готовими.
- Режим розробки включає залежності розробки; режим виробництва виключає їх.

### Зафіксовані менеджери пакетів

- npm, pnpm та corepack попередньо встановлені з зафіксованими версіями, тож збірки відтворювані.
- Corepack забезпечує доступ за потребою до Yarn та pnpm без окремого встановлення.
- Версії менеджерів пакетів незалежні від версії Node.js, що дозволяє оновлення без зміни runtime.

### Довіра до сертифікатів слідує за системним сховищем

- Node зібрано так, щоб перевіряти TLS за системним сховищем довіри, а не за копією Mozilla, вбудованою в офіційний бінарний файл.
- Кореневий сертифікат, вилучений із системного сховища Ubuntu або списком недовіри b19, одразу втрачає довіру, без очікування нового випуску Node.
- Сертифікати, додані до системного сховища, отримують довіру без налаштування `NODE_EXTRA_CA_CERTS`.
- `NODE_OPTIONS=--use-bundled-ca` повертає вбудовану копію.
